# ADR 0002: The time domain on GPUs with CubeCL

Status: accepted (2026-10-27).

## Decision

The time-domain leapfrog runs on GPUs through [CubeCL](https://github.com/tracel-ai/cubecl)
(MIT OR Apache-2.0), in its own crate `emcraft-fdtd-gpu` (L2, beside `emcraft-fdtd`).
`emcraft-fdtd` prepares a run as a `Plan` of plain arrays and hands it to a `Stepper`; the
CPU's threads stay the default and the reference.

- **Kernels in Rust.** CubeCL's `#[cube]` functions are Rust, type-checked with the rest of the
  workspace, and compile at run time to CUDA, HIP, Metal, SPIR-V, WGSL or the CPU's SIMD.
  Hand-written WGSL or CUDA C would put a second language in the solver.
- **Backends.** CUDA (the `cuda` feature; the driver is loaded at run time, so a
  build without CUDA installed runs and reports CUDA as unavailable) and CubeCL's CPU runtime,
  always built, which lets CI run the same kernels without a GPU. Others (wgpu: Vulkan and
  Metal; HIP) can be added as features; WGSL has no f64.
- **Precision.** Kernels are generic over the float type; single and double are both offered.
  Consumer GPUs run f64 at 1/32–1/64 of f32 (an RTX 3080: 1/64), but the leapfrog is bound by
  memory traffic, so double costs about the 2× of its bytes rather than 64×. Single is the
  default on a GPU and agrees with the CPU's double to 1e-6 on the high-pass filter, against
  the scheme's own 1e-2. The Fourier transforms stay on the CPU in f64.
- **Determinism.** Each value is written by one unit from the previous half step's values;
  the projections sum in a fixed order (fixed strides, then a fixed tree), no atomics. The
  same plan, device and precision give the same bits. Devices differ from the CPU's threads by
  rounding (fused multiply–adds, the sums' order), so their results are compared within a
  tolerance, not bit for bit.
- **No `unsafe`.** Kernel arguments are made through `TensorHandle`'s safe constructors, with
  each array's own length; launches are bounds-checked (`#[cube(launch)]`). A panic inside the
  runtime is caught at the crate's boundary and returned as `FdtdError::Device`.
- **Pinned.** CubeCL's API moves between minor releases: the workspace pins `=0.11.3` and the
  crate keeps every CubeCL call in two files.

Measured on an RTX 3080 (the high-pass filter, the threads on 16 cores): 1 mm cells 3.2 s →
0.39 s single, 1.26 s double; 0.5 mm cells (370 000 cells, 115 000 steps) 70 s → 5.6 s single,
23 s double.

## Not yet

Dispersive materials (the auxiliary equations) and open problems (the CPML on all faces,
lumped ports, the Huygens box) run on the threads only; a device refuses them. The frequency
domain's sparse factorization stays on the CPU: it needs f64 and its dense products are bound
by arithmetic, where consumer GPUs are slow in f64.
