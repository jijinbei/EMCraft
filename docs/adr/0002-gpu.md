# ADR 0002: The solvers on GPUs with CubeCL

Status: accepted (2026-10-27).

## Decision

The solvers' heavy loops run on GPUs through [CubeCL](https://github.com/tracel-ai/cubecl)
(MIT OR Apache-2.0), in their own crate `emcraft-gpu` (L2, after `emcraft-fdtd` and
`emcraft-solver`). The solvers stay free of it: `emcraft-fdtd` prepares a run as a plan of plain
arrays (`Plan` for the guide, `OpenPlan` for the open box) and hands it to a `Stepper` or
`OpenStepper`; `emcraft-solver` hands its factorization's large fronts to an `Accelerator` set
for the calling thread (`accel::with`). The CPU's threads stay the default and the reference;
`solve.device` chooses where the session's solvers run.

- **Kernels in Rust.** CubeCL's `#[cube]` functions are Rust, type-checked with the rest of the
  workspace, and compile at run time to CUDA, HIP, Metal, SPIR-V, WGSL or the CPU's SIMD.
  Hand-written WGSL or CUDA C would put a second language in the solver.
- **Backends.** CUDA (the `cuda` feature; the driver is loaded at run time, so a
  build without CUDA installed runs and reports CUDA as unavailable) and CubeCL's CPU runtime,
  always built, which lets CI run the same kernels without a GPU. Others (wgpu: Vulkan and
  Metal; HIP) can be added as features; WGSL has no f64.
- **Precision.** Kernels are generic over the float type; single and double are both offered.
  Consumer GPUs run f64 at 1/32–1/64 of f32 (an RTX 3080: 1/64), but the leapfrog is bound by
  memory traffic, so double costs about the 2× of its bytes rather than 64×. Single is the
  default on a GPU and agrees with the CPU's double to 1e-6 on the high-pass filter, against
  the scheme's own 1e-2. The Fourier transforms stay on the CPU in f64.
- **Determinism.** Each value is written by one unit from the previous half step's values;
  the projections sum in a fixed order (fixed strides, then a fixed tree), no atomics. The
  same plan, device and precision give the same bits. Devices differ from the CPU's threads by
  rounding (fused multiply–adds, the sums' order), so their results are compared within a
  tolerance, not bit for bit.
- **No `unsafe`.** Kernel arguments are made through `TensorHandle`'s safe constructors, with
  each array's own length; launches are bounds-checked (`#[cube(launch)]`). A panic inside the
  runtime is caught at the crate's boundary and returned as `FdtdError::Device`.
- **Pinned.** CubeCL's API moves between minor releases: the workspace pins `=0.11.3` and the
  crate keeps every CubeCL call in it.

Measured on an RTX 3080 (the high-pass filter, the threads on 16 cores): 1 mm cells 3.2 s →
0.39 s single, 1.26 s double; 0.5 mm cells (370 000 cells, 115 000 steps) 70 s → 5.6 s single,
23 s double.

## What runs on the device

- **The time domain, all of it.** The guide (four kernels a step: H, E with the dispersive
  edges' auxiliary equations, the source, the projections) and the open box (five: H, the
  ports' E before the step, E, the lumped ports and current elements, the Huygens box's running
  transforms in f64 with the batch's phasors made on the host). The host keeps the plan, the
  ports' Fourier transforms and the checks, reading back once a batch. The open box with two
  gaps and a dipole at 1 mm: 3.4 s on the threads, 0.12 s single, 0.39 s double.
- **The factorization's large fronts**, in complex double: the device holds the front; for each
  block of 64 pivots the host reads its columns back, finds the pivots (Bunch–Kaufman, the same
  code as the CPU's) and the device applies the interchanges and the block's update of every
  later column (tiles of 64 × 64 entries, 4 × 4 in each unit's registers, the 64 pivots staged
  16 at a time in shared memory, each entry summed in order). The update runs at about 210
  GFLOP/s on an RTX 3080, near half its f64 peak, while faer's on 16 cores reaches about 225:
  on such a card the device is no faster (the coaxial line's 75 750 unknowns: 2.7 s on the CPU,
  6.2 s with CUDA including the kernels' compilation). A data-centre GPU (f64 at half its f32
  rate) changes that; the path is there and checked, the CPU stays the default.
- **On the CPU still:** the pivots of each block, the triangular solves (memory-bound, column
  by column), assembly, meshing, the fast sweep's reduced basis and the eigen solvers' small
  dense problems — each cheap beside the factorization, or ill-suited to a GPU.
